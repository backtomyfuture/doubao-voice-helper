# 语音宏只做整句触发，命中即提前替换

语音宏的触发词都很短，只作为一次听写的全部内容出现；需要接后文时，用户分两次听写。因此 Macro Engine 只判断本次 Inserted Text 是否整句等于触发词（忽略标点、空格、大小写与全角半角），去掉了原来的句中替换。整句触发让我们能在听写停止后逐次检查已写入的文字：不可能命中时立即放弃（Early Reject），一旦等于触发词就立即替换（Early Replace），不再固定等待文字稳定。

## Considered Options

- **保留句中替换**：句中出现 “model”、“limit” 等词会被误替换，而且必须等整句稳定才能判断，速度上不去。
- **命中后等文字稳定再替换，或替换后继续观察一段时间**：更稳，但日志显示豆包在停止后常再改一次文字，会让中位耗时停在约 0.65 秒。用户选择速度优先。

## Consequences

- 豆包在替换之后补上的标点会留在文字里（例如 “/usage。”），写回校验把“替换结果后紧跟标点”视为成功，不会因此拦下回车。
- 一个触发词是另一个触发词的开头时（如 “model” 与 “models”），可能在豆包写完之前就按较短的那个替换；这里不做特殊处理，只在设置里提示用户避免这样配置。
- 以后如果要恢复句中替换，需要重新引入“等待稳定再判断”的路径，不要只改匹配函数。
