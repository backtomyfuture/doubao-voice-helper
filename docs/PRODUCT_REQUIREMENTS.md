# 豆包语音助手：产品需求与可行性评估

## 1. 文档状态

- 状态：架构设计输入，尚未进入开发
- 产品名称：豆包语音助手
- 目标版本：MVP
- 目标平台：macOS 14 及以上，仅 Apple Silicon
- 分发对象：少量熟人测试

## 2. 问题定义

豆包输入法已经提供语音识别，但现有交互仍要求用户频繁回到键盘：

1. 不能直接使用鼠标额外按键完成按住说话。
2. Agent 场景中的特殊字符和命令容易识别失败，例如“斜杠”无法得到 `/`。
3. 输入完成后的提交动作缺少按应用配置的自动化能力。
4. 当前原型依赖个人目录、LaunchAgent 和 Logi Options+ 私有配置，不适合交付给其他用户。

本产品不替代豆包语音识别，而是在 macOS 上提供一个本地增强层。

## 3. 合理性结论

| 需求 | 结论 | 说明 |
|---|---|---|
| 额外鼠标键触发豆包 | 合理且已由原型验证 | 可监听标准鼠标事件并模拟豆包快捷键 |
| 按住说话、松开结束 | 合理且风险较低 | 适合用明确状态机实现 |
| 自定义语音宏 | 合理，但有目标应用兼容性风险 | 只能后处理豆包输出，不能训练或修改豆包模型 |
| 自动回车 | 合理，但误提交风险高 | 应在第二阶段按应用单独启用，默认关闭 |
| 打包为独立 App | 合理 | 需要重建设置、权限引导、登录启动和分发流程 |
| 公开或 App Store 分发 | 暂不适合 MVP | 当前无 Developer ID，且全局事件与辅助功能能力需要额外审核 |

总体判断：**需求值得实现，核心鼠标触发链路成熟，语音宏链路需要先完成兼容性验证。**

## 4. 产品原则

1. **增强而非替代**：不录音、不调用语音模型，只控制豆包并处理其输出。
2. **本地优先**：设置、规则和运行状态只保存在本机。
3. **安全失败**：无法可靠定位本次文本时保留原文，不猜测、不回删。
4. **最小监听**：只监听被配置的额外鼠标键，不监听普通键盘输入。
5. **明确反馈**：开始、结束、失败和暂停都有可见状态。
6. **不侵入第三方**：不注入豆包进程，不修改 Logi Options+ 私有数据库。

## 5. MVP 范围

### 5.1 必须具备

- 菜单栏常驻 App。
- 独立设置窗口。
- 捕获可配置的标准额外鼠标按键。
- “按住说话，松开结束”交互。
- 可配置的豆包语音快捷键，默认左 Control。
- 可编辑的应用排除列表，排除时透传原鼠标行为。
- 仅处理本次鼠标触发听写产生的文本。
- 用户可维护任意“识别文本 → 输出文本”规则。
- 在本次文本内执行区分大小写的字面子串替换。
- 多条规则冲突时最长匹配优先。
- 内置少量可删除的特殊字符和 Agent 命令示例。
- 菜单栏状态和轻量屏幕浮层。
- 权限检查及引导。
- 首次启动询问是否登录启动，默认开启。
- 日志只记录元数据，不记录听写原文或规则内容。

### 5.2 首版验收应用

以下环境必须单独验证，不能用“支持终端”笼统代替：

1. Terminal.app
2. Ghostty
3. Cursor 或 VS Code 的内嵌终端

其他终端和 Agent 客户端先按“尽力兼容”处理。兼容列表必须显示真实验证状态。

### 5.3 明确不包含

- 自研语音识别。
- 录音或麦克风访问。
- 云同步、账号系统或远程分析。
- AI 重写、模糊匹配、正则规则或语法解析。
- 普通键盘输入的全局替换。
- 自动修改鼠标厂商配置。
- 首版自动回车。
- 首版规则导入导出。
- 首版自动更新。
- Intel Mac 和 macOS 13 及以下。

## 6. 核心用户流程

### 6.1 首次启动

1. App 解释自身只增强豆包，不处理音频。
2. 检查并引导开启辅助功能和必要的输入监控权限。
3. 用户进入“按键捕获”模式，按下要绑定的额外鼠标键。
4. 用户确认或录入豆包语音快捷键。
5. App 测试一次开始/停止快捷键。
6. App 询问是否登录启动，默认开启。
7. 用户可检查内置语音宏和应用排除列表。

### 6.2 正常听写

1. 用户在支持的目标应用中按住鼠标键。
2. App 捕获当前应用、窗口、焦点控件和文本快照。
3. App 触发豆包语音快捷键，显示“正在听写”状态。
4. 用户松开鼠标键。
5. App 再次触发快捷键，等待豆包输出稳定。
6. App 只对本次新增文本执行语音宏。
7. App 安全写回并恢复光标，或保留原文并提示失败。

### 6.3 安全中止

发生以下任一情况时，只停止豆包，不执行文本替换：

- 前台应用改变。
- 窗口或焦点控件改变。
- 原目标应用退出。
- 无法证明文本范围属于本次听写。
- 权限在会话中被撤销。

## 7. 语音宏语义

示例：

| 识别文本 | 输出文本 |
|---|---|
| 斜杠 | `/` |
| 斜杠批准 | `/approve` |
| 斜杠任务 | `/missions` |

规则要求：

- 只作用于本次听写新增文本。
- 使用原始 Unicode 字符串进行区分大小写的字面匹配。
- 先匹配更长的源文本。
- 同一位置只应用一条规则。
- 单次扫描，不递归处理替换结果，避免规则循环。
- 空源文本、重复源文本和完全相同的重复规则不能保存。
- 设置页应提供输入预览，但不需要 AI 或正则表达式。

## 8. 非功能要求

### 隐私

- 不申请麦克风权限。
- 不持久化焦点控件内容、听写文本或剪贴板内容。
- 不把设置和日志上传到网络。
- 崩溃报告和遥测默认不存在。

### 安全

- 全局事件监听只订阅必要的鼠标事件。
- 读取文本后只在内存中短暂保留，完成或失败后立即释放。
- 不在无法验证目标范围时模拟删除、撤销或重输。
- 不修改豆包、Logi Options+ 或其他第三方 App 的文件。

### 性能

- 鼠标按下后的状态反馈应近似即时。
- 监听空闲时不轮询前台应用或文本内容。
- 文本稳定等待必须有超时，不能无限阻塞下一次会话。

### 可恢复性

- App 崩溃不能让鼠标键或 Control 键保持按下状态。
- 重启后设置保持不变。
- 配置损坏时回退到安全默认值，并提示用户。

## 9. 验收标准

### 鼠标触发

- 可通过捕获界面绑定一个标准额外鼠标键。
- 在非排除应用中，按下时启动豆包，松开时停止豆包。
- 在排除应用中，鼠标事件完整透传。
- 冷却、重复按下和丢失 mouse-up 不会造成状态卡死。

### 语音宏

- “斜杠批准”可按用户规则变为 `/approve`。
- 替换不会修改听写前已经存在的文本。
- 最长规则优先且结果不递归替换。
- 切换焦点后不执行替换。
- 不支持的输入控件保留原文并显示非阻塞提示。

### 交付

- `.app` 内没有个人绝对路径。
- 新用户无需手工安装 LaunchAgent。
- App 内可以完成权限检查、登录启动和配置。
- 测试包提供清晰的 Gatekeeper 打开说明。

## 10. 后续路线图

### 第二阶段

- 按应用配置自动回车，默认关闭。
- JSON 规则导入导出，包含显式 schema 版本。
- 扩展并公布终端兼容矩阵。
- 更细粒度的浮层和故障诊断。

### 公共分发前

- 申请 Apple Developer Program。
- 使用 Developer ID 签名、公证和 Hardened Runtime。
- 评估 Sparkle 或等价更新方案。
- 完成品牌与商标审查。“豆包语音助手”可能被误解为官方产品，应增加非官方声明或改用中性名称。
- 重新评估 Mac App Store 对全局事件监听和辅助功能能力的限制。

## 11. 关键风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 不同终端无法统一暴露新增文本范围 | 语音宏在部分应用不可用 | 适配器架构、逐应用验证、安全降级 |
| 豆包输出完成时间不固定 | 过早读取会漏字 | 文本稳定检测加总超时 |
| 鼠标厂商驱动吞掉额外按键 | App 收不到事件 | 提供标准 HID 映射指南，不修改私有数据库 |
| 辅助功能权限过强 | 用户信任成本高 | 首启解释、最小监听、本地处理、无原文日志 |
| 未签名测试包受 Gatekeeper 限制 | 安装体验差 | 仅熟人测试并提供说明，公开分发前签名公证 |
| 豆包快捷键或行为变化 | 控制失效 | 快捷键可配置，提供自检，不依赖内部接口 |

## 12. 开发前置验证

正式开发前必须先用最小实验回答以下问题：

1. 三个验收应用是否能可靠获得听写前后的焦点文本与选择范围。
2. 豆包提交文本后，哪些可访问性属性会改变，变化时序如何。
3. 是否能在不触碰剪贴板、不猜测字符数的前提下替换精确范围。
4. 输入监控与辅助功能权限在 macOS 14、15、26 上的实际提示和恢复流程。
5. 鼠标释放事件丢失、系统睡眠和 App 切换时如何确保状态回到空闲。

如果某个验收应用无法满足第 3 条，应将其标为“仅支持鼠标触发，不支持语音宏”，而不是使用危险回退。
